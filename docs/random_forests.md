# Random Forest Models

## Purpose and inputs

This component fits three random forests to predict in-hospital death from the first
48 hours of Set A. The feature sets are values (111 predictors), recording patterns
(74 predictors), and their combination (185 predictors). No static descriptors,
severity scores, outcome-derived fields, or RecordID are used as predictors.

Features are generated by the unchanged `scripts/06_build_features.py`, using
`BP_RULE_B_V1`. Raw Set A data were copied from the existing local course-data
download; the personal-checkpoint feature tables and models were not reused.

The modeling run uses the supplied `split_assignments.csv`. A verified copy is retained locally under
`data/audit/supplied_split_assignments.csv`; the operational copy is under
`data/processed/`. Its SHA256 is
`96ce6b957987236e0d3ede0e8b475190cc340b4762447e9d22906ad188110828`.
The training/test and five-fold assignments are read from this file, not generated
by the random-forest code. Independent confirmation that this supplied file is the
exact file used for Kaiyan's reported results is pending.

## Methods

All models use the same 3,200 training stays, 800 test stays, and five training
validation folds. Tables are aligned by RecordID. Each pipeline uses median
imputation followed by constant-column removal and a random forest. Imputation
and column removal are fitted separately within each fitting fold. Entirely
missing fitting-fold columns are filled with zero and then removed as constant.
No extra missingness indicators or standardization are added. Zero measurement
counts are retained, and no stays are dropped for missing predictors.

The three feature sets use the same prespecified grid:

| Setting | Values |
| --- | --- |
| Trees | 300 (fixed) |
| Maximum depth | 8 or unrestricted |
| Minimum samples per leaf | 10 or 2 |
| Features considered per split | Square root of retained predictor count or 50% |
| Class weighting | None |
| Random seed | 707 |

There are eight candidates and five fits per candidate for each feature set.
Each feature set selects its own candidate with the highest mean validation
AUROC. An exact tie selects the first candidate in scikit-learn's ParameterGrid
order. This is a modest search, not an exhaustive optimization. Scores used to
select a candidate are tuning scores, not an unbiased estimate of final performance.

The selected pipeline is refitted on all training stays and produces one death
probability per test stay. The training script does not compute test AUROC, Brier
scores, calibration curves, thresholds, or test-driven model revisions. Xiaoning's
evaluation component will perform the common test-set comparison.

## Reproduction

Set up and activate the [shared project environment](environment.md).
This component uses Python 3.11.18 and the same root
[requirements.txt](../requirements.txt) as the other analysis scripts.

Obtain Set A and the agreed assignment file. Place the assignment file at
`data/processed/split_assignments.csv` before building features. Do not delete it
to generate a replacement split. The supplied raw-data downloader is available
if the raw files are not already present.

```bash
python scripts/download_data.py
python scripts/06_build_features.py
python scripts/12_train_random_forests.py --mode check
python scripts/12_train_random_forests.py --mode tune --jobs 4
python scripts/12_train_random_forests.py --mode predict --jobs 4
```

`--mode all` runs tuning and prediction together. Prediction verifies that input
file hashes and Python/package versions still match those recorded at tuning. A changed environment or source
dataset should be documented and validated before replacing an existing result.
